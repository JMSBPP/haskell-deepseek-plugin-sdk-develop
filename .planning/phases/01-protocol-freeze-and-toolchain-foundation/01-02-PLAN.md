<locked_decisions>
These come from `01-CONTEXT.md` and the phase's resolved open questions. They are
not open for reconsideration while executing:

- Requests use slashes (`tool/execute`, `guard/decide`, `subagent/run`); bare
  `initialize` and `shutdown` match the harness's own `HarnessSdkRequestMap`;
  notifications use dots (`section.changed`); `$/cancel` keeps its LSP spelling.
- A cancelled in-flight request **always** gets a `-32800` reply. A `$/cancel`
  for an unknown or already-completed id is silently ignored. `-32003 CANCELLED`
  from the ARCHITECTURE.md draft is retired.
- `-32001 PROTOCOL_VERSION_MISMATCH` **is** in the frozen table: the mismatch
  must be observable in `plugin.jsonl`, and a bare exit is not observable.
- `protocolVersion` is the integer `1`. Exact equality, no negotiation, no shim.
- Corpus id normalization: rewrite every id to an ordinal by first appearance
  **per direction** (`h1,h2,…` host-issued, `p1,p2,…` plugin-issued). Direction
  is decided by which side *originated the request*, so a plugin's response to
  a host request normalizes to `h1`, not `p1`.
- Windows and macOS CI lanes are deferred to Phase 2, deliberately, because this
  phase ships no transport to test.
</locked_decisions>

Harness host and an out-of-process plugin peer. Pre-1.0: no compatibility
promise, no shims, no deprecation window. `protocolVersion` is the integer `1`.

**2. Framing.** Newline-delimited JSON over stdio. One compact JSON object per
line, UTF-8 bytes, no embedded raw newline. A frame is `encode msg <> "\n"`.
Cite `deepseek-harness/packages/sdk/protocol/src/transport.ts:261` for the write
side and `:182` for the read side. stdout carries frames and nothing else;
diagnostics go to stderr.

**3. Envelope Rules.** `params` is **always a JSON object**. The harness's
`objectParams()` (`transport.ts:214,:222`) collapses an array or scalar `params`
to `{}`, so a non-object `params` is silent data loss and is rejected here with
`-32600`. **Batches are unsupported**: a JSON array matches neither id nor method
dispatch and is rejected with `-32600`. `id` is a string or a number, round-tripped
verbatim; a non-scalar id can never be echoed, so its error reply carries
`"id":null`. Unknown members are dropped when a frame is rebuilt. Example:
`corpus/malformed-shape/{host,plugin}.jsonl`.

**4. Handshake Manifest.** The manifest is the `result` of `initialize`. The
normative example is `corpus/handshake/plugin.jsonl`; quote it. Then a field
table:

| Field | Type | Meaning |
|---|---|---|
| `protocolVersion` | integer | must equal the host's; see section 5 |
| `pluginInfo` | `{name, version}` | identifies the peer in host logs |
| `tools[]` | `{name, description, parameters, output:{schema}, presentation:{mode}}` | `parameters` and `output.schema` use only the harness's supported keyword subset (`type`, `oneOf`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `const`, annotations); `output.schema` is mandatory; `presentation.mode` is static and decided at declaration time |
| `guards[]` | `{id, match:{tools[]}, failPolicy:"open"\|"closed"}` | `failPolicy` is what the host applies when the guard throws, times out, or the peer is dead |
| `sections[]` | `{name, order, text}` | static text carried in the manifest, so a section costs zero round trips |
| `subagents[]` | `{name, description}` | providers the host registers for delegation |

Tool names must match `/^[A-Za-z0-9_-]{1,64}$/`. A name outside that set fails
activation loudly; the host never normalizes it.

**5. Versioning.** Integer, compared for exact equality. No negotiation, no
capability exchange, no shim. On mismatch the plugin replies `-32001` with both
versions in the message, serves no contribution, and exits non-zero — an error
frame is observable, a bare exit is not. Example:
`corpus/version-mismatch/{host,plugin}.jsonl`.

**6. Methods.** Copy this table verbatim:

| Direction | Method | Kind | Params | Result |
|---|---|---|---|---|
| host → plugin | `initialize` | request | `{protocolVersion, hostInfo:{name,version}, cwd}` | the manifest |
| host → plugin | `tool/execute` | request | `{callId, tool, arguments}` | `{value, content}` |
| host → plugin | `guard/decide` | request | `{guard, callId, tool, arguments}` | `{kind:"allow"\|"deny"\|"ask", reason?}` |
| host → plugin | `subagent/run` | request | `{runId, subagent, prompt, cwd}` | `{stopReason, lastAssistantMessage?}` |
| host → plugin | `shutdown` | request | `{}` | `{}` |
| host → plugin | `$/cancel` | notification | `{id}` | — |
| plugin → host | `section.changed` | notification | `{name, text}` | — |

State the naming rule under the table: requests use slashes, except bare
`initialize` and `shutdown`, which match the harness's own `HarnessSdkRequestMap`;
notifications use dots, matching `session.event` and `subagent.started` in the
same file; `$/cancel` keeps its LSP spelling.

**7. Error Codes.** Copy this table verbatim:

| Code | Name | Meaning |
|---|---|---|
| −32700 | `PARSE_ERROR` | malformed JSON line |
| −32600 | `INVALID_REQUEST` | not a JSON-RPC 2.0 frame, including a batch array, a non-object `params`, or a non-scalar `id` |
| −32601 | `METHOD_NOT_FOUND` | unknown method |
| −32602 | `INVALID_PARAMS` | params fail the method's record |
| −32603 | `INTERNAL_ERROR` | unhandled exception inside the SDK — operator-actionable |
| −32800 | `REQUEST_CANCELLED` | the handler observed cancellation (LSP's code) |
| −32001 | `PROTOCOL_VERSION_MISMATCH` | handshake versions differ; activation fails loud |
| −32002 | `UNKNOWN_CONTRIBUTION` | tool, guard, section, or subagent id absent from the manifest |
| −32004 | `TOOL_FAILED` | the author's handler failed — a domain failure the model reads |
| −32005 | `INVALID_ARGUMENTS` | model arguments failed the declared schema |
| −32006 | `SHUTTING_DOWN` | a request arrived after drain began |

Add two sentences after the table: the `-32004` / `-32603` split is load-bearing,
because both surface to the model as an error but only `-32603` is an
operator-actionable log line. `-32003 CANCELLED` from the early architecture draft
is retired and must not appear in any implementation.

**8. Cancellation.** `$/cancel` is a notification carrying `{id}`. A running
handler **always** resolves with `-32800`, so a host waiter — in particular the
`tools/pre-execute` waterfall — can never wedge on a cancelled request. A
`$/cancel` for an unknown or already-completed id is silently ignored: no error
frame, no crash, no log line above `debug`. Examples:
`corpus/cancel-inflight/`, `corpus/cancel-late/`, `corpus/cancel-unknown/`.

**9. Lossless JSON and Number Policy.** An integer outside the JavaScript safe
range, ±(2^53 − 1), is **rejected**, never rounded. Implementations inspect the
raw frame text for unsafe integer tokens rather than trusting a parsed value,
because `JSON.parse` rounds silently — mirror the harness's
`code-runtime-python` stance. Non-finite numbers and negative zero are rejected.

**10. Hostile Input.** Every inbound frame is shape-validated and **rebuilt**,
never cast: forged extra fields never ride along, and a non-scalar id can never be
echoed into a reply. A junk line becomes a `-32700` error frame rather than an
exception, and the reader stays in sync for the next line
(`corpus/malformed-junk-line/`). The reader is bounded by a configurable
`maxFrameBytes`; a frame exceeding it is rejected with an error frame instead of
being buffered. The default value of `maxFrameBytes` is Phase 2's to set and is
a validated config field, not a hardcoded constant.

**11. Id Namespaces.** Host-issued and plugin-issued request ids live in separate
namespaces and never collide. The concrete scheme is implementation-private; the
corpus normalization rule in section 12 makes it invisible to conformance
comparisons.

**12. Conformance Corpus.** Layout: `corpus/<scenario>/host.jsonl` carries the
frames the host sends, `corpus/<scenario>/plugin.jsonl` the frames the plugin must
emit, in order. A **zero-length `plugin.jsonl` means the plugin emits no frames**
(see `corpus/cancel-unknown/`); it is not an unwritten stub. A scenario carrying
`EXPECTED.md` is a known-red scenario whose first line names the phase that must
turn it green; when the last `EXPECTED.md` is deleted, the corpus is fully
implemented.

Then the normalization algorithm as language-neutral pseudocode, so two
implementations cannot disagree:

```
normalize(hostFrames, pluginFrames):
    origin  = {}                       # request id -> "h" | "p"
    counter = { "h": 0, "p": 0 }
    label   = {}                       # (side, id) -> normalized label

    for frame in the two files merged in wire order:
        side_of_file = "h" if the frame came from host.jsonl else "p"

        if frame has "method" and frame has "id":       # a request
            origin[frame.id] = side_of_file

        if frame has "id" and frame.id is not null:
            side = origin[frame.id]                     # a response inherits
                                                        # the requester's side
            if (side, frame.id) not in label:
                counter[side] += 1
                label[(side, frame.id)] = side + counter[side]
            frame.id = label[(side, frame.id)]

        if frame is a "$/cancel" notification:
            id = frame.params.id
            frame.params.id = label[(origin[id], id)]   # unchanged if unknown

    return the frames
```

State the consequence explicitly: **direction is decided by the side that
originated the request, not by the file the frame appears in.** A plugin's
response to host request `h-1` normalizes to `h1`, never `p1`. Comparison is
decode-then-compare on normalized frames, because JSON object key order is not
significant and aeson's key order is not declaration order.

**13. Shutdown.** A `shutdown` request returns `{}` and the peer then exits
cleanly. stdin EOF is equivalent to `shutdown`. SIGPIPE is a clean exit, not a
crash. No orphaned threads and no in-flight handler survive either path.
Example: `corpus/shutdown/`.
